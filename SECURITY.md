# 🛡️ Security Policy — MAXA Cyber Security Framework

At **MAXA Cyber**, we take the security, integrity, and safety of our tools and users extremely seriously. This document outlines our security policy, supported versions, and the process for reporting potential security vulnerabilities responsibly.

---

## 📋 Supported Versions

We actively provide security updates, bug fixes, and security patches for the following releases of the **MAXA Cyber Framework**:

| Version | Supported          | Security Patches |
| :---    | :---:              | :---:            |
| `v3.0.x`| 🟢 Yes (Active)    | Full Support     |
| `v2.0.x`| 🟡 Maintenance     | Critical Only    |
| `< v2.0`| 🔴 End of Life     | No Support       |

If you are using an older version, we strongly recommend upgrading to the latest release to ensure you have the newest security updates and features.

---

## 🚨 Reporting a Vulnerability

If you discover a security vulnerability, flaw, or potential exploit within any repository or tool created by **MAXA Cyber**, please **DO NOT** create a public GitHub Issue. Publicly disclosing a zero-day vulnerability can put users and environments at risk.

### Preferred Reporting Channels:

Please report security issues privately through one of the following channels:

- 📩 **Direct Telegram**: [@maxaCyber](https://www.google.com/search?q=https://t.me/maxaCyber)
- ✉️ **Security Email**: `security@maxacyber.uz`
- 🔒 **GitHub Security Advisory**: Use the **"Report a vulnerability"** button under the repository's **Security** tab.

---

## 📝 What to Include in Your Report

To help us investigate, triage, and patch the issue efficiently, please include as much detail as possible in your initial disclosure:

1. **Vulnerability Type**: (e.g., Command Injection, Insecure Deserialization, Hardcoded Credentials, Buffer Overflow).
2. **Affected Tool / Module**: (e.g., `smart_unzip.py`, `cyber_pulse.py`, `maxa_cyber_100.py`).
3. **Step-by-step Proof of Concept (PoC)**: Clear instructions or script demonstrating how to reproduce the issue.
4. **Impact Assessment**: What an attacker could achieve if the flaw is exploited.
5. **Suggested Fix / Remediation** *(Optional)*: If you have a proposed patch or pull request ready.

---

## ⏳ Security Response Timeline

When you report a security vulnerability to **MAXA Cyber**, you can expect the following response commitment:

- **Initial Acknowledgment**: Within **24 hours** of receiving your report.
- **Triage & Validation**: Within **48–72 hours** to confirm the vulnerability and assess its severity.
- **Fix & Patch Release**: Within **3 to 7 days** depending on the complexity and severity of the issue.
- **Public Disclosure**: A Security Advisory and release note will be published after the patch has been tested and deployed.

---

## 🛡️ Safe Harbor & Rules of Engagement

We fully support responsible security research and value contributions from White Hat researchers, Red Teamers, and security enthusiasts. We commit not to pursue legal action against researchers who adhere to the following **Safe Harbor** guidelines:

- **Authorized Testing Only**: Only test targets, servers, and systems you own or have explicit, written authorization to audit.
- **No Data Destruction**: Do not destroy, modify, or exfiltrate private data beyond what is strictly necessary to demonstrate a PoC.
- **No Service Interruption**: Do not perform Denial of Service (DoS/DDoS) attacks, spamming, or social engineering against users or infrastructure.
- **Responsible Disclosure**: Allow us reasonable time to investigate and fix the reported issue before sharing details publicly.
